# 独立交付与描述一致性

每次输出前读取。目标是把本次实际采用的规则落实到每套画面说明，不是复述整份技能或堆积禁词。羽饰构造仍只由 [form-family.md](form-family.md) 定义；本文件检查信息是否传递、是否互相矛盾。

## 交付单元与信息落点

每套正向、负向和建议参数共同构成一个交付单元。正向本身须明确生成意图并描述成立的画面，不能依靠负面词补出缺失结构；三部分不得互相否定。批量中的每套均须脱离对话独立成立，但独立不等于详尽复述：删除修辞、解释、同义重复、内部检查项和画外细节，只保留重建本图所需的最小充分关系。

## 可复制交付格式

每套交付单元使用独立的普通 Markdown 围栏代码块包裹，标题、正向提示词、负向提示词和建议参数全部放在同一个代码块内，便于一键复制。代码块不指定语言，不使用行内代码或嵌套代码块。代码块内依次使用“标题：”“正向提示词：”“负向提示词：”“建议参数：”四个标签，并在各部分之间留空行。批量输出时每套单独成块；审核说明、动作总览和差异说明放在代码块外，避免混入可直接投喂生成器的文本。

| 内容 | 必须落在本条实际描述中的信息 |
| --- | --- |
| 人物与服装 | 成年身份、可辨外观、所选服装的可见结构、材质及必要覆盖；不凭空补未核实的角色设定 |
| 眼羽 | 实际锚点与固定或凝聚方式、跨面路径、形态、头部相对尺度、所选材料怎样遮住双眼，以及表面如何避免眼形；不得只写编号或“全遮眼” |
| 动作与视角 | 支撑、关键肢体任务、躯干与脸部朝向；人物自身左右、相机所在侧和高度分开说明，不能只写歧义的“左前三分之二角度” |
| 场景与构图 | 人物和环境的空间关系、画面边界、实际可见的场景内容；不为完整而给画外部位堆细节 |
| 场景几何 | 建筑/道具与人物共享的相机、焦距、消失方向、支撑平面和前后遮挡；柱体、拱券、台面、地面和接触面不能只用“透视正确”概括 |
| 光影与材料 | 光源方向与软硬、需要时的补光/反射、不同材料怎样受光；检查该机位和光照下覆盖与锚点仍成立，不把“电影感”当作具体照明 |
| 组图一致性 | 本套实际固定的外观和允许变化的维度；若动作、场景、机位或光线变化，不能再写“仅开放形态变化” |

采用角色能力联动时，在本条写出实际材料或元素行为、服装关联和覆盖机制，不用角色名或技能名替代视觉描述；设定来源与原创设计的区别在提示词外简短说明，不把检索过程塞进正向。

布局编号、Form、strict 等可作为参数标识，但不是生成器已掌握的规则。按既定规则选定方案后，在正向展开实际内容，不把规则的多个可选分支原封不动交给生成器选择。

参数中的布局编号与 Form 名称仅供用户记录方案，不能代替结构描述。若写入“布局05、收束”等标识，必须同时写出锚点位置、羽流路径、覆盖方式、外端收尾和形态边界；接收方只看到参数标识时，不能假设它知道本技能的编号定义。

参考图保真与补全必须分流：先写明参考图锁定的人物、服装、姿态和相机关系，再写允许变化的眼羽、光线或场景。补齐被裁剪的鞋子只有在用户允许扩展画幅或重构取景时执行；用户明确保留裁切的单张不得强行补全。补全时必须同时描述脚底支撑、地面延伸、透视和接触阴影，不能只在正向末尾追加“完整鞋子”。

交付前按三道门检查：正向结构是否自洽，负面是否只补充而没有否定正向，参考图/建筑/人体是否共享同一空间关系。三道门任一失败时，先修改正向结构或交付分流，不靠继续堆叠负面词解决。

## 失败复核与证据边界

同一眼羽问题连续两次失败后，停止继续追加同义负面词。重新检查：①正向是否把羽片写成了会产生眼形负空间的几何；②布局与 Form 是否在当前头部姿态下成立；③眼羽是否与发饰、王冠、服装装饰混为一体；④参考图保真是否压过了眼羽改造；⑤输入图和生成方式是否适合该修改。修订必须先改变失败的结构关系，不能只增加“禁止眼睛”。

审查时分开登记四类结果：规则/结构缺陷、提示词传递缺陷、模型执行未通过、外部平台或工具限制。整图生成和局部重绘是不同输入条件，结果不能直接互相证明。用户主动进行的裁剪、拼接、合成或其他外部处理，只能作为本轮测试的案例证据，用于判断技能缺陷和模型边界；不能写入技能默认工作流，不能作为提示词交付能力，也不能替代自包含提示词。

局部重绘不是省略描述的理由。即使只编辑眼羽区域，交付单元仍须独立说明人物/参考图保持项、编辑区域、形态、布局、锚点、羽流进入眼区的路径、连续遮挡机制、材质、层叠、厚度、受光、禁止改变项和局部范围。不得写“沿用原眼羽”“按前文修复”“保持原结构”而不展开实际结构。

## 材质、结构、光影联合检查

- 分别描述衣料和眼羽，不能因同色或同材质就把衣裙的透明度、褶皱和飘动全部继承到眼区。说明眼区与外端各自的密度、叠层及受光表现；二者允许不同，不要求所有材料都做透明外端。
- 不能用“密褶、错位、完全遮眼”替代具体安排。按统一构造展开哪些完整羽面跨过覆盖区域、线脊/卷边/色块如何衔接或结束，以及所选光照下为何不会留下眼状长弧。非实体元素按羽流单元、密度和边界表达，不擅改为固体。
- 单枚裁片的梭形轮廓、暗色羽轴或金属反光也可能参与构成假眼，不只检查接缝。保持羽片可辨，不通过消除全部纹理、阴影、曲线或缩掉外端来规避。
- 侧视、俯拍、后掠和逆光方案逐套检查近侧、鼻梁与远侧的覆盖关系，以及锚点可见性。补光只改善可见细节，不能自动使透明材料变得不透视；不能依赖过曝、死黑或模糊掩盖未解决的结构。
- 用户锁定的材质若与所需效果冲突，先在允许范围内调整同材质构造与摄影方案；仍无法协调时指出具体取舍，不偷偷换材料、增加异质底板或声称物理效果已验证。仅在需要用户选择才能继续时询问。

## 参考与跨图身份

技能读过图片不等于另一生成器收到图片。能转成文字的可见特征写入每套；确需图片锁定的脸、服装或结构，明确列出该套需同时提供的图片及各自用途。附图条件与文字独立性分开：没有该图时不声称已锁定，文字完整也不能保证跨图同一张脸。

先检查附件实际是否可供接收方使用，不用本地路径、附件序号或“上一张”代替传图。用户未提供身份基准时描述已知外观，不虚构身份一致性。不能为核对传图而阻止已有信息足够的提示词修订。

## 输出前的独立阅读

单独阅读眼羽段：是否能说出本副设计的轮廓或羽流特色、支撑它的工艺与连接，以及当前画面如何使它可见？只剩通用覆盖、配色和一个扣件时，设计表达尚未完成，应重写实际造型关系，而非增加赞美词。再分别检查面前佩戴遮挡与表面无眼睛意象，不能认为写了“图层在上面”便同时解决两者。

暂时不依赖历史、总览和技能文件，逐套检查：接收方能否确定上述画面关系，是否仍需猜测“它、同款、严格一致、参考尺寸”指什么。再把正向、负向和参数放在一起核对，优先改写冲突句，不能在末尾追加禁令抵消冲突。

正文已有某规则但表达不充分，归为描述缺口；正文前后相反，归为冲突；规则仅在技能或历史中，归为传递遗漏；规则明确但成图仍违背，只能记录未执行，不能从成图推断模型内部原因。以上可并存。

文本检查只说明完整性与一致性。实际效果须在明确授权的新成图中核验：分别检查露眼、假眼、材料、布局/形态、锚点及画面关系。需要比较修订效果时尽量保持人物、视角和光线等条件一致，记清变化；不同场景的旧图不当作控制实验。未获得出图授权则止于文本修订，不报告视觉修复成功。

## 迭代交付与输入条件

用户要求完整提示词时，修订也交付完整、自包含的正向、负向与参数，标题和整套内容放在同一个可复制单元；审核说明放在单元外。局部修改范围不等于只交一段补丁。不把完整提示词宣称为必然优于局部编辑。

已知无参考图时，删除“随附图片”“保留参考人物”等依赖，按文字定义人物与服装；有参考时明确继承与排除的维度，不能同时要求连接换款又原样保留该连接。记录本轮上传情况与已知历史上下文，未重新上传不等于没有历史图像影响。不同输入条件的结果可比较可见差异，不能据此推断模型选择了最简单路径或证明某句话独立起效。

分辨率默认采用平台默认或自动尺寸，不自动写8K、超高清等标签；显式尺寸要求按平台实际能力处理，不以平台未承诺的尺寸判造型失败。检查画质修订没有改动锁定的服装纹饰、装饰密度和构图，正负段不以“无纹理”否定必要材质。取景裁切与景深清晰范围分开判断，已接受的裁切不在后续审核中反复要求修复。
